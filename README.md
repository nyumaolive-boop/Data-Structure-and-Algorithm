# DCOMP320 Stack Implementation

Author: Josephine Olive Nyuma
Course: Data Structures and Algorithm

A Python command-line program evaluates one mathematical expression per line using a custom Stack class and two-stack infix evaluation. It does not use eval(), exec(), or an external expression evaluator.

## Files
- stack_evaluator.py — stack class, tokenizer, evaluator and file processing.
- input.txt — the assignment's three sample expressions.
- output.txt — actual output generated by the program.
- test_stack_evaluator.py — automated verification.
- Stack_Implementation_Report.docx — formatted written report.
- TEST_RESULTS.txt — recorded test run.

## Run on Windows
1. Install Python 3.10 
2. Open the Stack_Assignment folder in VS Code.
3. Open Terminal > New Terminal; make sure it is in this folder.
4. Run `python stack_evaluator.py` (or `py stack_evaluator.py`).
5. Open output.txt. Edit input.txt and run again for new expressions.

No third-party libraries are required. The default paths are relative to the terminal's working directory. To use other files:

```sh
python stack_evaluator.py other_input.txt other_output.txt
python -m unittest -v
```

## Input and output
Each expression occupies one line. Blank lines and separator lines consisting of at least three hyphens are preserved in order, including their surrounding spaces. Other separator characters are unsupported. Expressions cannot span several lines.

Input:
```text
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

Output:
```text
13
-----
16
-----
-10
```

The sheet prints 17 for the second example. The expression evaluates to 2 + 14 = 16, so the program produces 16.

## Supported syntax and limitations
Supports +, -, *, /, nested parentheses, whole numbers, decimals, unary plus/minus and whitespace. Multiplication/division take precedence over addition/subtraction. Binary operators of equal precedence are evaluated left to right. Write `2 * (3 + 4)`, not `2(3 + 4)`.

Fraction arithmetic preserves exact intermediate results for decimal input. Whole-number answers are printed exactly. Other answers use Decimal with 12 significant digits and may use scientific notation. Exponents, functions, variables, scientific-notation input, %, // and ** are unsupported.

Malformed expressions or division by zero produce an `Error: ...` line in that expression's position; later lines are still processed. The program exits with code 1 if any expression fails or a file cannot be read/written, otherwise 0. Output is overwritten on each run; input and output must be different paths. Extremely large inputs may require substantial memory or arithmetic time.
